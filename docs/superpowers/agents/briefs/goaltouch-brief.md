User report (Android phone, GoPro LRV + MP4):
1. **Thumbnails 1 and 3 of 6 are black** (the goals are clearly visible in the footage). Cause: `grabFrame` (frameGrab.ts) draws on `seeked`, which on Android can fire before the frame is painted. Fix: after the seek, wait for `requestVideoFrameCallback` where available (fallback: seeked + a short wait); if the drawn frame is still (near-)black, retry once (e.g. after a short wait or a tiny nudge in time). Pure helper for the "is this canvas black" check with a unit test. Applies to every grabFrame user.
2. **Use the full MP4 for the picture when there is one.** `GoalSetup` passes `first?.url` (the playback file = the LRV proxy when paired; see `VideoSourceFile.kind/fullFile` in src/types.ts) to `useGoalPicture`/`useThumbnails`. Keep thumbnails + scrub frames on the playback file (fast), but take the sharp still (step 1 on, `STILL_WIDTH` 3840) from an object URL of `first.fullFile` when present (create/revoke in an effect), falling back to the playback URL if that fails (e.g. the browser can't decode it). Marks are normalised 0–1 so LRV/MP4 share them (same framing) — keep it that way.
3. **Crosshair jumps after each point** (PostPlacer ~line 86–95 pans to `guessNextPoint` after every point on touch). User finds it unhelpful: stop auto-panning between points; keep the current view. (Keep the initial start view for the first point.)
4. **Landscape phone: Set point is pushed off screen** (steps 5 and 6 especially). Fix the layout so the action is always visible at 844×390 and 915×412 (touch): e.g. a side column for controls in landscape with the primary action pinned. ALSO add: **tapping the crosshair itself sets the point** (a tap without drag within ~44 px of the crosshair centre = Set point; a drag still moves the picture). Update the touch instruction/aria text to mention it ("…then tap the crosshair or press Set point").
5. **Dragging a placed point to edit it doesn't work on touch** (dots have pointer-events none on touch). Give touch a way to edit: tapping a placed dot (or its number in the diagram) makes it the current point, centres the picture on it, and Set point / crosshair tap replaces it; then continue with the next unplaced point. Desktop drag/click behaviour unchanged.
6. **Copy** (user: "frame one goal" is ambiguous — the frame or a goal scored?). Replace ZOOM_INSTRUCTION with: "Replays of goals scored at this end zoom in to this view. To frame one goal’s replay differently, select that goal in the events list and press Framing." Update the test.
